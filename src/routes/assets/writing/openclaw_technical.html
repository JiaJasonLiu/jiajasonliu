My AI Agents

At the beginning of this AI hype and the introduction of OpenClaw, it flooded my news. Initially, I didn't see the purpose of it. However, I soon saw companies starting to improve AI abilities for downstream tasks (e.g., coding and summarizing notes), showing a shift from general machine learning algorithm improvements to specific AI use cases.

The Setup

For security reasons—such as preventing OpenClaw from accidentally deleting my files or committing secrets to GitHub—I pulled the git repo and ran it in a Docker container. The setup to use an API key was relatively simple. I created a Telegram account and connected to it; it was a strange experience being able to text my AI agent (which I named Aura) about what I wanted it to do. The beauty of Telegram is that it fully supports bots and groups of them, so I could have multiple agents with different responsibilities at my fingertips.

After playing around with it, I realized that an agent is essentially just a gateway between an AI (the brain) and a terminal (the hands and feet). It is the body that connects the brain to the world to perform tasks based on user information.

Key Insight An agent = gateway between AI (brain) + terminal (hands and feet). It connects thinking to action.

I spent two days understanding its inner workings, from its "Heartbeats" to its memory. The token usage was initially insane, so I stripped everything it didn't need. For instance, I removed the Heartbeat, which consumed tokens every 30 minutes, and restricted its ability to control the gateway itself (e.g. changing its own config).

I also added an Ollama container to my setup so I could use local models like Qwen Coder and Llama 3.1. While it could handle simple chats, it was still too slow and inefficient at tool calls. Eventually, I chose to use Google API keys, as they offer a generous free tier for models with reasonable throttling.

The Essence of the Playbook

The essence of this model is its ability to have memory and its own workspace. I used this to create multiple agents with respective workspaces, identities, and purposes.

I initially kept the AGENTS.md files as empty as possible, containing only their names and purposes. When they do something unexpected, I update these files so they don't repeat the mistake. I call these files their "Playbook"—the rules they must abide by. As I improve my prompting, the agents' behavior becomes much more predictable.

The Reality Check: Security & Stability

The truth is that even though you are offloading thinking to an AI, you still spend mental effort wondering how the AI is performing.

On the technical side, CVE-2026-25253 (WebSocket hijacking) shows that any new tech has issues. We should wait for them to become stable before full adoption. In the meantime, always run them in a Docker container for safety. Furthermore, these repos get updated almost every hour; things break if you pull the most recent changes. I recommend choosing a stable tag and making a branch off of that.

Future Plan

I was planning on building an agent myself, but OpenClaw has become such a "beast" that it's more efficient to tweak existing code. I plan on exploring other repos like PicoClaw (Golang) for speed and efficiency. Big companies like Nvidia and Claude will likely start making their own OpenClaw replicas soon.

This is only the beginning of gateways where AI can control your devices. So, I look forward to seeing how these develop in the future.

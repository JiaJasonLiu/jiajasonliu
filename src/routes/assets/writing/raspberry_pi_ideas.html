I Have a Raspberry Pi and No Excuse Not to Use It

I've had a Raspberry Pi 4 sitting in a drawer for about a year now. Every few months I'd pick it up, think "I should do something with this," and then put it back. Classic.

I finally sat down and actually thought about what I'd want running 24/7 on a tiny silent computer that costs about £4 a year in electricity. Turns out, quite a lot.

Pi-hole — The First Thing You Should Run

If you do nothing else with a Raspberry Pi, run Pi-hole. It's a network-wide DNS ad blocker — every device on your Wi-Fi gets cleaner browsing, no browser extension needed. Ads on your TV? Gone. Ads in apps? Gone. It's genuinely one of those "why didn't I do this sooner" moments.

Setup is a single bash command, and you get a dashboard showing how many queries it's blocked. Mine was blocking about 18% of all DNS requests in the first 24 hours. That number alone made me weirdly proud.

Self-Hosted Everything

The rabbit hole I actually want to go down is self-hosting. There's something satisfying about owning your own data stack — not for some ideological reason, but because it's actually a great way to learn infrastructure while building things you'd actually use.

The list I'm working through:

  • Uptime Kuma — monitoring for my personal projects. Dead simple to set up and gives you a nice status page.
  • Gitea — a self-hosted GitHub. Not replacing GitHub for real projects, but useful for private notes, configs, and experiments I don't want in a cloud.
  • Immich — self-hosted Google Photos. The UI is actually great, and backing up photos to my own NAS via a Pi feels right.
  • Portainer — just Docker management via a browser. Running containers on a headless Pi is fine via SSH, but having a UI is genuinely useful when you have 10 containers running.

All of these run in Docker Compose. One YAML file, one docker compose up -d, done. I wish I'd learned Docker Compose properly years ago — it's such a clean way to manage this kind of home lab setup.

A Cheap Kubernetes Node (Sort Of)

This one is more "learning" than "useful" — but I want to set up a small k3s cluster using the Pi as a worker node alongside my old laptop. k3s is a lightweight Kubernetes distribution that runs perfectly on ARM.

I don't need Kubernetes at home. But I work with it at work and being able to actually experiment — deploy things, break things, understand the scheduler — is worth more than reading docs. Learning Kubernetes by clicking around in a managed cloud cluster never really clicked for me. Owning the physical nodes does.

The Agentic Angle

Given that I've been building AI agent setups lately (running them in Docker, wiring them to Telegram), the Pi is a natural always-on host for lightweight agents. Something that checks my calendar, sends me a daily digest, or monitors a project's GitHub issues and pings me when something needs attention.

Nothing heavy — no local LLM (the Pi 4 doesn't have the grunt for that). Just an agent that uses an external API but runs locally, with no cloud dependency for the orchestration layer. I like the idea of my own hardware making the decisions, even if the model lives somewhere else.

The Real Value

The Raspberry Pi isn't the best tool for any of these things individually. A cloud VPS is faster, a NAS is better for storage, a proper server is better for everything else. But the Pi forces constraints that are actually useful for learning — limited RAM, ARM architecture, no GUI by default. You have to understand what you're running to make it work.

And there's something about having it physically in the room. A box on my desk that's quietly doing things. It makes the infrastructure feel real in a way that a cloud dashboard doesn't.

So yeah. No more leaving it in the drawer.
